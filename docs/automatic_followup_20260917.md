# 后续实验自动衔接

用户授权：后续实验和操作排入进程，前一步结束后接续。本轮采用服务器持久队列衔接确定性作业，Codex自动跟进负责结果解释、代码修复及后续研究决策；不把尚未实现的生成方法写成已经可运行的任务。

## 当前前置结果

四条完整PBHC开发动作各完成2,000次更新（49,152,000环境步），共196,608,000步；每条4个固定检查点，共16组评测已经完成。最终模型在原随机化条件下逐帧严格通过率均为0。保留全部结果，不以“进程完成”代替“基线合格”。

服务器调度器为`scripts/pbhc_followup_queue.py`，清单、冻结哈希及逐任务状态在`records/pbhc_followup_20260916/`。每张卡只运行一个任务；每任务结束即检查收据并接续，GPU未释放则短暂等待。队列可重启并按已校验收据跳过完成项；失败或半成品不直接覆盖，不无限重试。原训练队列未被中断或修改。

这12组均为已有固定策略的评测，不增加控制器训练，也不构成数据生成收益。nominal的32个环境不是32个独立示范来源；不以较容易的条件下通过来宣布原任务已解决。

## 后续决策和自动跟进

已创建当前任务的自动跟进：每15分钟检查进程与结果，在实质进展、完成或失败时处理，不重复汇报无变化状态。它负责读取失败诊断证据，继续用户已授权的工程修复和实验步骤、归档以及GitHub更新。新训练或新数据方法必须有明确实现、预算和验证协议，不能预先承诺其成功或无限启动任务。

当前完整生成器、独立格斗接触标注、多来源测试集及正式数据效用条件仍不完整。它们在后续决策清单中保留，**并未假称全部已经变成服务器可执行作业**。若基本执行仍失败，则先修复证实的问题；若只在扰动下失败，则分开报告基本跟踪和鲁棒性，检查评价与任务条件的关系，不修改原成绩。

本轮完成报告、归档和确定的后续处理后，自动跟进应暂停；没有新增可行动状态时不循环追加实验。

无扰动下马步冲拳可作为基本执行正例，但不证明其随机化鲁棒性；勾拳和侧踢能完成动作仍不满足全程位置精度；回旋踢应先定位早期终止。下一阶段不应简单对全部动作统一追加训练，也不能继续仅调整根高度。这些是开发诊断线索，不是独立最终验证。

改变事件配置也会改变随机数消耗；相同seed不保证各环境具有完全相同的扰动实例。因此no_push与原条件的差异是条件诊断，不能声称是逐实例配对因果估计。nominal去掉多类扰动，也不能据其改善独断是哪一项造成了失败。
