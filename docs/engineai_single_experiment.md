# 双人生成方法向 PM01 单人场景迁移

本轮是工程可行性试验。核心仍是参考动作数据生成，跟踪算法只用于检验数据。现有双人 TIMotion 模型与动作身份连续性修正保持不变，取每个生成角色的完整轨迹，转换为 PM01 单人无对手训练（shadowboxing，空击练习）。这叫双人分布的单角色提取，不是已经训练好一个独立单人扩散模型。双方均保留，不能仅挑选看起来容易的角色；角色编号不能自动当作攻击者/防御者标签。

## 实验实现

固定原生成目录 `runs/timotion_generic_24_seed2026_identity` 的前三对，分别对应出拳/闪避、踢击/退步、格挡/反击的文字条件。它们是历史开发样例，不是独立测试集；文字条件也不是人工核验过的动作类别真值。

1. 3 对 × 2 角色 = 6 条人体参考，复用骨架连续性处理。
2. 使用官方 PM01 SDK 关节结构，通过带关节角限制的位置 IK 重定向。尺度由机器人/人体骨盆到脚踝长度比估计。手部用官方末端碰撞几何附近的局部目标点；不能声称精确解剖对应。
3. 两组对照：原始 IK；关节角/速度/加速度约束优化。两组保持动作时长与根部轨迹相同，加速度 100 rad/s² 是研究筛选参数，不是厂家额定值。
4. 使用官方 PM01 USD 和电机参数，在 Isaac Lab 中导出正确关节/身体顺序的 50 Hz 跟踪参考。
5. 先做官方模型物理步进、官方示例跟踪接口校准，再测试生成动作。参考回放与真实动力学执行分别记账。
6. 跟踪训练复用官方 PM01 任务的观测、奖励和终止条件，以现有 RSL-RL2.3 PPO 参数接口接入。是兼容实现，不能声称精确复现官方2.3.2运行环境。

单人分支不保留人与人接触损失：独立空击没有真实对手，不能继续用“拳头触及对方身体”作为成功标准。第一轮只测试关节约束。地面接触、靶位接触和完整动力学约束仍需单独加入、消融和验证，不能把本轮包装为完整迁移完成。

## 评估标准与来源

不存在本轮已核实的、统一适用于所有机器人的“格斗动作合格分数”。采用可复现的指标组合，并把论文指标、官方任务条件和本研究阈值分开。

|层次|指标/计算方式|解释与限制|
|---|---|---|
|动作语义|盲评 Punch/Kick/Block/Dodge/组合动作正确率；双人转单人角色一致性|需要独立标注，不用输入提示词自动当真值|
|生成分布|FID、R-Precision、Diversity、Multimodality|HumanML3D惯例；必须使用对应单人表示、固定评估器与足够独立样本。本轮6条不能给有意义FID，不能套用双人FID|
|运动学|关节角越界率、速度超限率、加速度筛选超限率、IK末端误差|报告物理单位、阈值来源；有限差分时间步必须一致|
|约束代价|相对未修正动作的关节偏移、动作路径保留比例、拳脚速度变化|防止把停止不动或过度平滑误当成改进|
|几何|脚滑、漂浮、穿地、自碰撞|参照PhysDiff类别；接触推断是几何代理，不是实测接触力|
|真实执行|固定起点完成率、关节MAE/RMSE、根部/身体位置误差、首次失败时间、力矩饱和|必须由物理步进产生，不能逐帧设置姿态。跟踪终止不必然等于跌倒|
|训练价值|V vs V+G普通 vs V+G约束，同预算分别训练，独立动作测试|当前种子是视频恢复V；没有传感器MoCap对照M时不能声称替代MoCap|
|成本|候选数、有效动作秒数、生成/修正/训练GPU小时、人工筛选时间|同时报告拒绝比例与多样性|

HumanML3D正式来源：[CVPR2022论文](https://openaccess.thecvf.com/content/CVPR2022/html/Guo_Generating_Diverse_and_Natural_3D_Human_Motions_From_Text_CVPR_2022_paper.html)。

物理指标参考：[PhysDiff ICCV2023](https://openaccess.thecvf.com/content/ICCV2023/papers/Yuan_PhysDiff_Physics-Guided_Human_Motion_Diffusion_Model_ICCV_2023_paper.pdf)，区分 Penetrate（穿地）、Float（漂浮）、Skate（脚滑）。本实验若采用不同几何或单位，不能直接与论文数值横比。

平台依据：[EngineAI官方仓库](https://github.com/engineai-robotics/engineai_rl_lab)、[PM01官方跟踪配置](https://github.com/engineai-robotics/engineai_rl_lab/blob/14ec57be718586bd0ac45375aa1115bd896fbdbc/source/engineai_rl_lab/engineai_rl_lab/tasks/tracking/config/pm01/flat_env_cfg.py)。工程资源不代替学术新颖性证据。

## 分阶段判定

- 模型加载、200步物理推进、CUDA反向传播通过：仅环境可用。
- 数据导出通过：仅格式与关节顺序正确，还需SDK/USD前向运动学一致性审计。
- PD诊断失败：当前简单控制器失败，不证明动作在所有控制器下不可执行。
- 单参考PPO试验：原计划从零训练300轮×256环境×24步；基线校准后改为下述官方先验100轮微调。仅检查小预算可学习性，不能作为正式多种子结论。
- 只有固定学习算法、多个训练种子、独立来源测试上的数据组对照，才能支持“生成数据提高训练价值”。

工程严格跟踪阈值沿用历史诊断：关节平均绝对误差<0.3 rad，平均根部位置误差<0.15 m，平均身体位置误差<0.15 m，且完整通过参考时长。它们是本研究预先声明的诊断阈值，不是行业标准。误差在首次失败前统计，必须与完成率一起报告；失败后自动重置的片段不能计入成功。

## 实施时发现并保留的问题

- 30Hz约束后插值会重新引入加速度超限。正式本轮PPO输入已改为先重采样50Hz再约束；初次12条和PD诊断保留在 initial30hz / pd_diagnostic 目录，最终输入为 references_50hz / tracking_references_50hz。切换发生于生成动作训练启动之前。
- SDK与USD的四个固定末端子框架位置定义不同，全部身体不能声称一致。实际关节身体前向运动学最大偏差低于1微米；官方跟踪目标不包含这四个固定子框架。跟踪参考全量身体数据由目标USD重新计算。
- Isaac Lab2.1缺少新版 quat_apply_inverse 名称，使用数学等价的单位四元数共轭旋转兼容；保留原终止条件。首次接口失败日志保留。

## 基线校准后的执行修订

官方公开 dance.pt 经新旧Actor接口转换，8组随机输入与官方ONNX输出最大误差9.54e-7。完整示例固定起点1220步评价：32/32环境完成，但按严格全局误差阈值仅2/32通过。这说明“没有倒”和“准确跟随全局轨迹”不同。

从零300轮官方示例训练完成，固定起点0/32完成（首次终止31–89步）。所以停止未完成的普通生成冷启动训练，并取消尚未启动的约束组冷启动；不把中止当完成。两组改用相同公开Actor/Critic初始化，重置优化器和探索标准差0.3，不启用观测归一化，均100轮、256环境、24步，614400环境步。外部先验数据必须披露，不能用于“从零减少MoCap依赖”的结论。结果是参考可学习性试验，尚非数据集扩增价值实验。

初次官方预训练评价被默认10秒episode超时截断，所有环境在500步结束，不能当物理失败。该记录保留，完整评价把episode时限延长到参考结束之后；训练规则保持不变。生成动作不足5秒，不受这项修正影响。

## 最终结果（2026-09-16）

两组各100轮、614,400环境步，均完成训练和固定起点32环境评估。使用同一官方策略初始化，单训练种子、单参考序列；约束组是同一序列的另一版本。

|方案|完整执行|严格跟踪通过|关节MAE/rad|身体位置误差/m|首次终止步数范围|
|---|---|---|---|---|---|
|普通重定向|0/32|0/32|0.41155|0.24563|7–45|
|关节约束|0/32|0/32|0.37579|0.25901|6–19|

评价目标为247个控制步，50Hz。误差只计首次终止前，汇总为有效存活样本加权值；不同存活长度影响可比性，不能把关节误差较小单独解释为方法有效。跟踪终止不等于已经判定跌倒。32环境不是32个独立训练种子。

因此：**单人数据提取、PM01重定向、真实Isaac物理执行和PPO验证链路可用，但当前生成数据在该预算和验证器下未通过；尚未证明训练价值。** 最终50Hz关节约束数据的限位/限速/加速度筛选通过，只覆盖运动学必要条件。地面接触、根部/支撑协调、初始化、动力学和参考适配仍需排查；当前证据不能把失败唯一归因于生成器、重定向或控制器。官方示例与生成动作任务不同，官方示例完成也不能排除控制器适配问题。

下一步限定为数据侧诊断：检查根部高度、脚底姿态、接触时序与初始状态；与同表示、相近速度的已知可跟踪短片段做正对照，再测试地面接触修正。通过该门槛后才扩展独立来源、多个种子的生成数据增益实验。不要持续改动跟踪器后把增益归因于数据。

结果和失败日志：`records/engineai_single_v1/`。可视化：现有HTML `#engineai-single`。视频分别标注参考回放和实际Isaac执行状态；SDK几何渲染不构成MuJoCo跨仿真器验证。冷启动中止记录、初次30Hz方案、错误超时评价均保留并标明用途，不覆盖成成功结果。
