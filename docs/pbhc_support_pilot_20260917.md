# 准备阶段支撑诊断与数据修正对照

本轮在 nlp03 服务器完成4组原始参考接触诊断及8组修正参考评估；新增策略训练步数为0。复用原来的4个2000更新检查点，每项32个环境、seed123、无扰动条件。32个环境不是32个独立动作来源。研究对象仍为示范数据构建，本轮没有改控制器、奖励或成功阈值。

## 新增证据

- 只增加接触/状态记录的4次执行，完整执行率、严格通过率、平均误差与此前无扰动评估逐项相同。
- 侧踢在0.20秒时，固定环境0的左脚位置误差约24.4厘米；0.44秒首先违反严格指标，0.54秒根位置误差超过15厘米。不能把后者当成最早失败。
- 回旋踢在1.70秒因环境的末端高度误差项 `ee_body_pos` 终止；该时刻右脚位置误差约1.05米。终止发生在几何严格标准失败之后，不能仅以未倒地判断成功。
- 初始根位置/关节与参考一致，因此没有证据表明该无扰动评估从错误的初始姿态开始。参考初始足部几何距地面约1.4–1.6厘米，动作内部也出现穿地代理量。
- 力信息来自仿真接触传感器，是刚体合计法向接触力，不是人体接触真值、摩擦力或分离的脚—地接触对。URDF胶囊下边界是几何代理，不能据此宣称接触力或动力学可行性。

## 两种修正及公平性

1. `ground_align`：仅对全段根高度作约1.5厘米的常量平移，测试初始落地偏移是否足以解释失败。
2. `prep_support`：在上述对齐基础上，只优化准备阶段的12个腿部关节，修正几何穿地和可信来源标签对应的近地支撑。目标包含足部水平位置、朝向、关节保真与时间平滑项；单关节变化最多0.12弧度，准备阶段两端衰减为零。

未知接触标签0.5未被当成接触/非接触真值；几何非穿透项也不等同于接触监督。没有将策略执行的姿态反写为参考。整段帧数、50Hz采样、根XY和朝向、上肢关节、主要拳脚阶段及后续关节轨迹均保留。修正后的速度重新由转换器计算；变化边界不意味着高阶导数已获得动力学保证。

对候选同时报告相对于原始参考及候选参考的误差。原始随机扰动结果继续保留为主结果。本轮只比较冻结策略对不同参考的响应，不宣称训练收益。评估终止仍由使用当前输入参考的原环境决定，均值须与完整执行率一起解释。

## 结果与决定

|动作|原始根误差均值|准备支撑修正后|原始严格通过|修正后严格通过（对原始目标）|
|---|---:|---:|---:|---:|
|勾拳|0.1355米|0.1044米|0%|0%|
|马步冲拳|0.0619米|0.2057米|100%|0%|
|回旋踢|0.1215米|0.1746米|0%|0%|
|侧踢|0.4172米|0.2575米|0%|0%|

回旋踢三组都提前失败；固定环境0的执行时长依次为原始1.70秒、仅对齐1.62秒、准备支撑修正1.42秒。其误差均值受执行时长截断影响，不可据均值单独排名。完整三组结果见 `records/pbhc_support_repair_20260917/report.md`。

**本轮不接受将准备支撑修正统一应用于全部动作。** 勾拳、侧踢的平均误差有所下降，但没有达到严格标准；马步冲拳出现明确退步；回旋踢仍未解决。几何约束改善不是充分的执行质量保证。固定的单动作策略也可能不能适应参考变化，因此失败不能证明修正数据不可学习。

**几何基线需特别区分：** `protocol.json` 的 `preparation_foot_penetration_before_m` 是“先做整体高度对齐后、尚未做关节修正”的中间量，不是原始数据穿地量。向下整体平移虽消除初始悬空，却加重后续穿地；本轮准备阶段修正没有恢复原始数据的最大穿地水平。以下均为同一URDF胶囊代理、同一准备帧集合，不能解释为真实接触深度。

|动作|原始准备阶段最大穿地代理|对齐＋关节修正后|
|---|---:|---:|
|勾拳|约3.80厘米|约5.19厘米|
|马步冲拳|约3.49厘米|约4.72厘米|
|回旋踢|约5.01厘米|约5.53厘米|
|侧踢|约5.30厘米|约6.66厘米|

因此本轮不能声称相对于原始数据“几何穿地改善”。初始帧落地与整段接触一致性是两个不同目标，后续必须同时报告两者。

下一阶段应先建立动作级数据质量验收：保留原始动作作为基线，检查修正对支撑转换、速度/加速度、技能保真和执行的共同影响，拒绝破坏已通过动作的候选。通过后再预先固定数据组，采用同一控制方法、相同初始化种子与训练预算进行原始/修正数据训练对照；不能挑每个动作最好的版本冒充统一算法，也不能继续盲目叠加高度修正或延长训练。

## 可复现与限制

- `scripts/evaluate_pbhc_support_diagnostic.py`：终止/自动重置前记录32环境的状态、估计驱动力矩、法向接触力和终止项。
- `scripts/prepare_pbhc_support_repair.py`：只读原始参考/机器人几何生成两种候选。
- `scripts/run_pbhc_support_repair.py`：两GPU、8项有限队列，禁止覆盖/重复启动，冻结输入及执行代码哈希。
- `scripts/summarize_pbhc_support_repair.py`：原始/修正双目标计分。
- `scripts/verify_pbhc_support_pilot.py`：检查8个候选的不变量及28个历史指标文件未改变。
- `support_analysis_v2.json` 修正了诊断摘要将成功轨迹的末帧哨兵值误写为失败时间的问题；成功改记为null，原评估指标未改变。旧版保留作为追踪记录。
- 当前为4个开发动作的仿真试验，不是双人格斗、独立测试集、多种子统计或合成数据效用证明。
